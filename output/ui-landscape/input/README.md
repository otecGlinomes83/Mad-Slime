# Исправление блокировки меню

Воспроизведено на текущей основной сцене: RuntimeWindows выключен. Стартовая ежедневная рулетка добавлялась в MenuPopupStack и блокировала MainMenuWindow, но оставалась невидимой под неактивным родителем. Диагностика до исправления: NAV Main, popup=True; MainMenuWindow interactable=False/blocks=False; RouletteView active=False.

Исправление: RuntimeWindows включён в сохранённой сцене. UiSpawner.SetParent активирует назначенный контейнер, поэтому скрытие контейнера при редактировании больше не оставляет невидимый попап с заблокированным меню. После исправления тот же выключенный контейнер активируется при запуске, рулетка видна и получает ввод.

В основной Menu.unity также восстановлены проверенные профили меню, размеры кнопки рулетки и увеличенные иконки. Другие части текущей сцены сохранены.

## Проверка

Проверка запускается из текущих файлов основной сцены; отдельно перед входом в Play Mode контейнер намеренно выключен для регрессии. Использован виртуальный Mouse Input System: события нажатия и отпускания проходят через включённый InputSystemUIInputModule. Сначала проверяется верхнее попадание EventSystem.RaycastAll; прямые вызовы Button.onClick и ExecuteEvents не используются.

В 1080×1920 и 1920×1080 нажаты все пять кнопок меню; подтверждено открытие соответствующего окна, закрытие его крестиком, пустой стек попапов и восстановление взаимодействия. Закрыта стартовая ежедневная рулетка. Кнопка Play загрузила Game. Проверены реальные размеры всех пяти кнопок 460×210. Runtime errors=0.

После проверки файлы Menu.unity и UiSpawner.cs в основном проекте побайтно совпали с файлами проверенной копии, SHA256 записаны в tested-files.json. Служебные тестовые скрипты, настройки и сохранения остались в отдельной копии.

Если в Unity всё ещё открыта прежняя версия сцены в памяти, выйди из Play Mode и заново открой Menu.unity с диска. Сохранение прежней открытой сцены может вернуть старые параметры поверх исправленного файла.
