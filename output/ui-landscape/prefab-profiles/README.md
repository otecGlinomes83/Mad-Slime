# Настройка ориентаций прямо в префабах

Открой префаб двойным щелчком и выбери объект с `Responsive Canvas Layout`. Для обычных окон это корень; в `FillUI` отдельные компоненты находятся на `PauseButtonCanvas` и `FillProgress`.

1. В Game View выбери нужное разрешение: **1920×1080** для горизонтали или **1080×1920** для вертикали.
2. Открой префаб и редактируй его во вкладке **Scene**. Область и профиль автоматически следуют Game View, даже когда выбран дочерний объект.
3. Нажми **Записать в Portrait/Landscape**, затем **Ctrl+S** (или используй Auto Save).
4. Перед сменой ориентации запиши ручные правки: при смене ориентации применяется сохранённый профиль. Смена разрешения в пределах той же ориентации не перезаписывает ручную расстановку.

В инспекторе **Размер области → Из Game View (автоматически)** — режим по умолчанию. Явные Portrait/Landscape остаются как дополнительные фиксированные форматы; в них Game View не управляет областью. Размер области соответствует логическим единицам Canvas Scaler Expand: например, 1920×1080 и 2560×1440 используют одинаковые UI-координаты.

Область редактирования временная. На время предпросмотра редактор показывает Canvas в World Space, включая служебный Canvas окружения Prefab Mode. Перед сохранением исходные режим Canvas, масштаб, геометрия корневого Rect Transform и настройки Canvas Scaler восстанавливаются. Сразу после сохранения, в том же вызове обработчика, область возвращается к предпросмотру; восстановления на следующий кадр больше нет. Временные параметры не попадают в игровой префаб. Undo/Redo поддерживаются.

Основная панель паузы имеет разные размеры: Portrait **960×960**, Landscape **1360×900**. Ранее оба профиля были 960×960, поэтому смена профиля не давала визуально горизонтального окна.

В `RouletteView` есть список **Вариант рулетки**: ежедневная с кнопками и рулетка скинов без кнопок. У каждого варианта своя пара профилей, которую записывают те же две кнопки. Размер и положение рулетки больше не задаются жёстко из runtime-кода. При единственной доступной кнопке действия она автоматически центрируется по горизонтали.

## Что записывается

Для назначенных RectTransform сохраняются якоря, pivot, anchoredPosition, sizeDelta и равномерный Scale. Шрифты, цвета, спрайты, вращение и настройки Layout Group общие для обеих ориентаций. Ползунки громкости настраиваются через родительский Slider; заполнение и положение бегунка управляются самим Slider. Размеры содержимого с Content Size Fitter/позиции элементов Layout Group не фиксируются профилями.

## Подготовленные префабы

Проверены все 20 UI-префабов в `Assets/MadSlime/Resources/Prefabs/UI`. Девять содержат систему ориентаций, всего десять компонентов:

- Buttons/PauseButtonCanvas
- FillUI (PauseButtonCanvas и FillProgress)
- LoadingScreen
- Menu/LeaderboardMenu
- Menu/PauseMenu
- ResultMenu/FailMenu
- ResultMenu/WinMenu
- Skins/RouletteView (оба варианта)
- WinPopup

Остальные — переиспользуемые элементы: кнопки, строки, сепаратор, колесо и другие компоненты родительских окон. Отдельная система ориентаций на каждом из них не нужна.

Вручную заполнять Targets для перечисленных окон не требуется. Ранее существовавшие профили сохранены. В `FillUI` процентный текст перенесён на дочерний `ProgressLabel` с сохранением ссылки: раньше Canvas находился на самом тексте и управлял его Rect Transform. В `RouletteSectorCard` удалён компонент отсутствовавшего старого скрипта; актуальная рулетка использует `RouletteWheel` и массивы иконок/надписей.

## Проверки

Отчёты рядом с этим файлом. Запись проверяется через обработчик настоящего Custom Inspector в открытом Prefab Stage, сохранение — командой File/Save, затем закрытием и повторным открытием префаба. Физическое нажатие мышью на кнопки записи не эмулировалось. Навигация в игре проверяется событиями мыши Input System через действующий UI-модуль, без прямого вызова onClick.
