# Архитектура приложения

> Гид по устройству кода Mad Slime. Числа и имена — по состоянию ветки `MadSlimeV2` @ `aa2c711`. Стиль кода и запреты — канон в `AI_RULES.md` (repo root). Карточки модулей — в папке **Модули**, карта связей — [[Граф модулей]].

## 1. Слои и сборки

| Сборка | Папка | Ссылается на |
|---|---|---|
| `MadSlime.Core` | `Scripts/Core/` | — только данные и интерфейсы |
| `MadSlime.Gameplay` | `Scripts/` (кроме `Core/`, `UI/`) | Core, VContainer, UniTask, InputSystem, UnityEngine.UI |
| `MadSlime.UI` | `Scripts/UI/` | Core, Gameplay, VContainer, UniTask, TMP, uGUI |
| *(Assembly-CSharp)* | `DI/`, `Saves/`, `Adapters/`, `Editor/` | всё, включая YG2-плагин |

Направление зависимостей строго однонаправленное: **UI → Gameplay → Core**. `Core` не знает ни про кого; `UI` не содержит геймплейной логики (только views/factories/service-рулетки).

## 2. Шов платформы (главное правило)

asmdef'ы не могут видеть Assembly-CSharp, где живёт YG2-плагин. Поэтому:

- Игра говорит с платформой только через 5 интерфейсов в `Core/Interfaces` — [[Интерфейсы Core (шов YG2)]]
- Реализации — 5 адаптеров в `Adapters/` ([[YG2-адаптеры]]) + partial `SavesYG` ([[SavesYG]])
- Точка сборки шва — [[ProjectLifetimeScope]] (`new Yg2SavesAccess()` и т.д.)
- **Прямой `using YG` вне `Adapters/` и `Saves/` — ошибка ревью** (проверено: нарушений нет)

## 3. DI-топология (VContainer)

```
ProjectScope.prefab (RootLifetimeScope, DontDestroyOnLoad)
├── PlayerProgress, PlayerUpgrades, LocalizationService
├── SfxPlayer, MusicPlayer, AudioMixerController
├── SO-ассеты: LevelsCatalog, TierTable, LayoutsLibrary
├── Singletons: LevelProgress, LevelConfigResolver, ItemPool, GameDirector
├── YG2-адаптеры (5 интерфейсов)
├── EntryPoint: SessionStateLogger
└── (родитель для всех сценических скоупов — неявно, через VContainer)
    ├── MenuLifetimeScope (7 ссылок)
    ├── GameLifetimeScope (34 ссылки)
    ├── ShopLifetimeScope (11 ссылок)
    └── FillLifetimeScope (18 ссылок)
```

- Сценические объекты — `RegisterComponent` (Scoped-инстансы существующих MonoBehaviour); SO-конфиги — `RegisterInstance`; безголовые классы — `Register(Lifetime.Singleton)`
- Инжекция — method injection `[Inject] public void Construct(...)`
- **Спавн через DI:** окна/карточки создаются только `IObjectResolver.Instantiate(prefab)` — иначе method injection не сработает (фабрики: [[UI-фабрики]], грид-фабрики магазина)
- **Авто-инжект звука кнопок:** `RegisterBuildCallback` каждого сценического скоупа обходит корни своей сцены и инжектит все `UIButtonSound` (включая неактивные) — дизайнеру остаётся назначить `SfxClip`
- Каждый скоуп валидирует свои `[SerializeField]`-ссылки (`ValidateAssigned`, fail-fast до построения контейнера)

## 4. Сцены и жизненный цикл

Единственная точка смены сцен — `GameDirector.LoadAsync(SceneId)` ([[GameDirector]]). `SceneManager.LoadScene` снаружи запрещён (и не встречается).

**Политика timeScale — три владельца, читать всем:**
1. [[Pauser]] (счётчик в каждой сцене): `RequestPause/RequestResume`, окна ставят/снимают автоматически ([[Окна | BaseWindow]])
2. [[GameDirector]]: при переходе ставит `timeScale = 1` **только если** `IAdsService.IsPauseGame == false`
3. [[Startup]] (Menu): нормализует `timeScale = 1` при запуске

Реклама ставит паузу сама (плагин, `autoPauseGame`); проект уважает это при resume. Известная дыра этой политики — [[Техдолг и баги | риск №4]].

**Переход (TransitionAsync):** гашение AudioListener/EventSystem/Canvas уходящей сцены → аддитивная загрузка с `allowSceneActivation = false` до 0.9 → активация → SetActive → выгрузка уходящей → восстановление EventSystem → обновление `PreviousSceneId`.

**Точки вызова:** [[MainMenu]] (Play/Shop), [[GameplaySessionHandler]] (→Fill), [[FillSessionHandler]] (→Game/Menu, с интерстишлом), [[ShopPanel | ShopCloseButton]] (возврат по `PreviousSceneId`).

**Bridge Game → Fill:** [[LevelProgress]] — project-скоуп синглтон; квота раунда переживает выгрузку Game и читается [[ShapeFillOrchestrator | FillCounter]] в Fill. Reset — только при генерации уровня.

## 5. Ключевые потоки данных

**Раунд:** `MovementKeyPressed` → Begin (resume, Timer, GameplayStart) → детекция per-frame → Collector → `ItemCollected` → Player: масса ([[PlayerTier]]) + квота ([[LevelProgress]]) → `QuotaCompleted` | `Timer.Finished` → пауза, delay 1 с → **Fill**

**Награда:** FillCompleted(percent) → Rewarder → Wallet.Add (Save) → `Win/Failed` → FillUIFabric → WinMenu/FailMenu → кнопки → FillSessionHandler (уровень++/Save/лидерборд) → interstitial → LoadAsync

**Мета:** ShopPanel/RouletteView → RouletteService (цены/роллы/таймеры по сейву) → Wallet/PlayerProgress (Save) → SkinApplier применит выбор в следующем Game

**Язык:** сейв непуст → язык игрока; иначе язык Яндекса (не сохраняется); ручная смена — пишется и стреляет `LanguageChanged` на весь UI

## 6. Паттерны и конвенции проекта

- **Fail-fast:** невалидная зависимость/аргумент → `InvalidOperationException` в Awake с текстом «Drag X into the _field field» (+ в каком скоупе регистрировать). Молчаливых early-return на невалиде не писать. Тексты исключений — фактическая документация по настройке скоупов
- **UniTask-канон:** `UniTaskVoid` + `.Forget()`, `GetCancellationTokenOnDestroy()` / linked CTS, `OperationCanceledException` ловится явно, Realtime-задержки под паузой
- **DOTween-гигиена:** `SetTarget` + `SetLink(gameObject, KillOnDisable)`, Kill в OnDisable; unscaled time (`SetUpdate(true)`) для UI под паузой
- **События:** `event Action<T>`, подписка/отписка строго парами OnEnable/OnDisable (OnDestroy), никаких анонимных лямбд
- **Данные — ScriptableObject:** весь контент уровней/экономики/звука — ассеты; генератор контента [[MadSlimeContentSetup]] создаёт и чинит их идемпотентно в batchmode (`-executeMethod MadSlimeContentSetup.SetupAll`)
- **Сейв-дисциплина:** [[PlayerProgress]] — единственная дверь к сейву, сам не сохраняет; `Save()` зовут потребители в явных местах (таблица в заметке); имена полей [[SavesYG]] заморожены (JSON-ключи живых сейвов)
- **Детекция:** `OverlapSphereNonAlloc` + буферы, никаких аллокаций в Update, LINQ в рантайме нет
- **Генерация уровня:** вся случайность локальна ([[LevelGenerator]] + ZoneLayoutPlanner + QuotaGenerator), конфиг всегда клампит параметры — квота гарантированно выполнима

## 8. Известные архитектурные компромиссы

- Сценические скоупы цепляются к корню неявно (parentReference пуст) — конвенция VContainer, не явная связь
- GameLifetimeScope — монолит на 34 ссылки вместо под-скоупов
- `InjectSceneButtonSounds` копипастится в 4 скоупах (просится базовый класс)
- Состояние timeScale размазано по трём владельцам (см. §4) — дыры в [[Техдолг и баги]]
- Полный список проблем и рисков: **[[Техдолг и баги]]**
