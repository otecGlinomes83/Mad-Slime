# Окружение, размещение предметов, адаптивный UI и производительность — план

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Оформить границы шести тем, обеспечить обзор игрока и размещение без пересечений, улучшить UI для разных размеров окна и затем совместно исследовать просадки при поглощении.

**Architecture:** Геометрия окружения создаётся через Blender MCP, подключается через LevelTheme и выставляется по существующим bounds пола. Существующий детектор перекрытий камеры обобщается для предметов и окружения; второй параллельный поиск стен не создаётся. Размещение проверяется глобально до спавна, UI перестраивается по фактическим размерам контейнеров.

**Tech Stack:** Unity 2022.3.62f2, C#, uGUI, Blender MCP, FBX, встроенный Imagegen, WebGL, Unity Profiler и Frame Debugger.

**Spec:** Запрос пользователя от 2026-10-19 в текущем чате; предлагаемые решения и критерии уточнены ниже. Статус: план для обсуждения. Реализация ещё не начата; художественные варианты и числовые бюджеты ниже — предложения агента.

## Global Constraints

- Размер карты фиксирован. Источник размеров — LevelGenerator.GetFloorBounds(); не увеличивать карту ради размещения или декора.
- Пользователь подтвердил: коллайдеры полностью охватывают модели. Использовать существующие коллайдеры как источник габаритов; отдельный аудит покрытия mesh не нужен.
- Шесть наборов по темам, переиспользуемых уровнями: Table 1–10, Room 11–20, Parking 21–30, City 31–40, Space 41–50, Universe 51–60. Перед исполнением повторно сверить LevelsCatalog.asset.
- Моделирование и экспорт окружения выполнять через живой Blender MCP. Сохранять редактируемые .blend и игровые FBX.
- Профайлер, Frame Debugger и исследование производительности — последний этап, вместе с пользователем. Ранние функциональные проверки не заменяют его.
- Финальные иконки кнопок — ровно 256×256 PNG, прозрачный фон, без запечённых надписей.
- Иконка внутри карточки скина увеличивается в 1,5 раза; исходный Icon в SkinItem.prefab — 100×100, целевой — 150×150. Не увеличивать автоматически всю карточку или 3D-превью.
- Разделители редкостей используют оформление PerkSeparator и локализацию ru/en/tr.
- Сохранить существующие сейвы, покупки, квоты, рост и выбор скина. Соблюдать Wiki/AI_RULES.md и существующий кодстайл.
- Сейчас разрешено создать план; продуктовый код, ассеты, билды и сцены в этом проходе не изменять.

## Review Focus

- Максимальный размер слайма, углы карты и несколько перекрывающих стен: персонаж виден, линия границы остаётся понятной.
- Пересекающиеся зоны, разные тиры, повороты и точки у края: все принятые предметы имеют непересекающиеся габариты внутри карты.
- Более редкая раскладка: хватает массы для роста и реально доступных предметов для квоты.
- Узкое, квадратное, широкое окно и изменение размера открытого меню: нет обрезаний, скачков выбора или потери прокрутки.
- Профилирование Editor, диагностического Player и обычного WebGL: результаты явно разделены; улучшения подтверждаются повторением того же сценария.

## Подтверждённое состояние проекта

- LevelPlacementPlanner сохраняет в списке препятствий только Large и выше. Общей проверки всех принятых предметов друг против друга нет.
- ClampToMap может сводить разные точки к одной границе; проверять нужно окончательные позиции после ограничения картой.
- ItemBody.Initialize назначает случайный поворот после планирования. Текущий круговой footprint от BoxCollider не зависит от Y-поворота, но его соответствие видимой геометрии требуется проверить.
- SkinRarityGroup.prefab: GridLayoutGroup 240×240, spacing 18, фиксированные три колонки. Заголовок находится дочерним объектом того же grid; _itemsParent указывает на корень группы. При переделке разделить заголовок и сетку.
- SkinsPagePresenter уже группирует скины по редкости. Сохранить эту логику, изменить представление групп.
- В Menu.unity есть контейнеры фиксированной ширины: например, UpgradesScroll — 1000 единиц Canvas. CanvasScaler сам по себе не перестраивает их содержимое.
- Уточнение после повторного чтения 2026-10-19: CloseItemDetector уже выполняет SphereCastNonAlloc от камеры до WorldCenter игрока и получает радиус через IRadiusRecipient. Поиск перекрытия уже есть; прежнее описание как проверки близости неверно для текущего кода.
- Ограничение — тип Item в коллекциях, событиях и GetComponentInParent. ItemGhostToggler дополнительно запрещает скрытие съедобных предметов через CollectAvailability.
- Detected сейчас вызывается для каждой обнаруженной цели каждый кадр, а не только при входе. При обобщении сохранить обновление доступности еды после тир-апа; нельзя заменить на enter-only без альтернативного обновления.
- ItemVisual уже использует GhostDither, MaterialPropertyBlock и плавное исчезновение; переиспользовать подход, не выдавать окружение за съедобные Item.
- GhostDither имеет только общий Tint и не читает исходные текстуры: при его подстановке исходное оформление заменяется одноцветным. Учесть это в материалах окружения.
- LevelSurface создаёт толстую платформу и нижний фон. Новое окружение должно заменить лишний видимый обрыв, а не просто добавить стены поверх прежней композиции.
- Причина лагов при поглощении пока не измерена. Ни один подозреваемый компонент не объявляется причиной без захвата профайлера.

## Предлагаемый внешний вид

| Тема | Граница | Что видно за ней |
| --- | --- | --- |
| Стол | Деревянный поднос с четырьмя бортиками и оформленными углами | Продолжение столешницы, салфетка, крупная чашка |
| Комната | Стены с плинтусами, закрытой дверью и окном | Фрагменты интерьера там, где их открывает скрытие стены |
| Парковка | Бетонное основание ограды, секции забора, закрытые ворота | Улица, газон, силуэты гаражей |
| Город | Парапет набережной по периметру | Вода, берег и упрощённые кварталы вдали |
| Космос | Технические опоры и энергетическая граница | Станционные конструкции и спокойный космический фон |
| Вселенная | Отличающаяся от космоса пространственная оболочка | Искажённый звёздный фон и редкие геометрические узлы |

Начать с четырёх групп сторон и отдельных углов. Если исчезновение целой длинной стороны выглядит резко, разбить её на немногочисленные секции. Не объединять весь периметр в один renderer. Нижний бортик можно оставить видимым, если он не перекрывает персонажа.

Рабочий бюджет на активный набор: до 20 тыс. треугольников, до трёх общих непрозрачных материалов и одного материала эффекта; без дополнительных realtime-источников света. Уточнить по первому набору и окончательно оценить на последнем этапе. Не обещать производительность только по числу полигонов.

## Task 2: Обобщение существующего скрытия при перекрытии игрока

**Files:**
- Modify: `Assets/MadSlime/Scripts/Collectables/Detection/CloseItemDetector.cs`, `Assets/MadSlime/Scripts/Items/Ghost/ItemGhostToggler.cs`, `Assets/MadSlime/Scripts/Items/Model/ItemVisual.cs` — обобщение без второй системы детекции.
- Общая цель поиска — компонент на объекте, обозначающий участника скрытия; не Item. Контракт визуального исполнения при необходимости — `IGhostVisual.SetGhost(bool isGhost)`. Наличие интерфейса не переносит в визуальный компонент правила доступности еды.

**Interfaces:** Детектор сообщает о перекрытии общей цели. Отдельная система переключения принимает решение: для еды запрашивает CollectAvailability по Definition.Tier, для окружения учитывает только перекрытие. Визуальный компонент исполняет SetGhost и не знает, может ли игрок съесть объект. Item остаётся держателем Definition без логики прозрачности и доступности. Точный выбор компонента-маркера или интерфейса поиска остаётся предметом проектирования; прежний аргумент о двух политиках внутри самих объектов исключён.

- [ ] Проверить текущее GhostDither: сохраняются ли цвет и текстуры, корректны ли тени и глубина. Выбрать совместимый материал окружения; не заменять все его материалы бесцветным ghost-материалом вслепую.
- [ ] Сохранить существующий SphereCastNonAlloc и масштабируемый радиус. Сначала проверить покрытие габарита на всех тирах; несколько дополнительных направлений вводить только если тест выявит пропущенные перекрытия.
- [ ] Заменить привязку поиска к Item на общую цель скрытия, отделённую от Item. Маска включает нужные слои предметов и окружения; собирать все перекрывающие цели, дедуплицировать несколько коллайдеров одной группы. Решение о скрытии принимает отдельная система, визуальный компонент только исполняет его.
- [ ] Проверить тир-ап при непрерывном перекрытии, отключение/уничтожение цели и несколько одновременных стен; для интерфейсных ссылок учитывать Unity-жизненный цикл владельца.
- [ ] Плавно скрывать перекрывающую группу и восстанавливать её после освобождения обзора; добавить небольшой запас/задержку от мерцания на границе.
- [ ] Не создавать новые материалы и массивы в каждом кадре. При отключении, паузе и смене темы корректно сбрасывать состояние.
